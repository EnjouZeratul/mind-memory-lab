# 工程约定

## 代码组织

- **单文件单职责**：分块、索引、适配器、端口各自独立；禁止“万能工具箱”式大文件。
- **无创世文件**：入口层只做装配与配置，不承载领域算法。
- **可替换宿主**：与 UI/Node 相关的薄层不得污染 `c/` 与核心类型定义。

## 语言策略

- **C**：对字节级分块、指纹与轻量启发式统计提供可移植实现；头文件即契约。
- **TypeScript**：编排、I/O、HTTP 与存储后端；在原生模块缺失时提供等价回退实现，并与 C 版本保持测试对照（指纹等）。

## 质量与风格

- 以测试覆盖关键不变量：路径沙箱、分块边界、指纹一致性、预算裁剪单调性。
- 依赖选择遵循“默认可安装、可审计、可替换”；避免引入仅为演示服务的重量级栈。

## 用户可见文案

- 语气：**理性、客观、可检验**，并允许体现青年研究者的朝气与问题意识。
- 禁止面向终端用户的“对 AI 开发者表功式”措辞（例如强调“已修复/已完成模型提示”等）。
- **界面与控件文案**：只保留操作与状态所需的最短说明；不得把架构或实现层叙述写进前端（例如「注入模型上下文」、工作区与模型如何组装、具体存储/检索栈名称等）。此类内容仅写在 `docs/` 或代码注释中。

## 性能

- 热路径优先使用增量索引与批处理事务；避免在请求路径上对同一文件重复全文扫描。
- 原生模块为可选加速项；不得将未编译原生模块视为错误安装状态。

- 合入前自查表见 [convention-compliance.md](convention-compliance.md)。
